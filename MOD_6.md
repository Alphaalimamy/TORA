## 6.1 The Mathematics of Data

### 6.1.1 The Data-Generating Process

In research, we assume that our data is generated by some (unknown) probability distribution $ p_{\text{data}}(\mathbf{x}, \mathbf{y}) $ over inputs $ \mathbf{x} \in \mathcal{X} $ and targets $ \mathbf{y} \in \mathcal{Y} $. The goal of learning is to find a model $ f_\theta $ that approximates the conditional expectation:

$$
f_\theta(\mathbf{x}) \approx \mathbb{E}[\mathbf{y} \mid \mathbf{x}]
$$

or, more generally, the conditional distribution $ p(\mathbf{y} \mid \mathbf{x}) $.

Since $ p_{\text{data}} $ is unknown, we approximate it with a finite sample:

$$
\mathcal{D} = \{(\mathbf{x}_i, \mathbf{y}_i)\}_{i=1}^N \sim p_{\text{data}}(\mathbf{x}, \mathbf{y})
$$

The **empirical risk** is the average loss over this sample:

$$
\mathcal{L}(\theta) = \frac{1}{N} \sum_{i=1}^N \ell(f_\theta(\mathbf{x}_i), \mathbf{y}_i)
$$

Minimizing the empirical risk is our proxy for minimizing the true risk $ \mathbb{E}_{(\mathbf{x}, \mathbf{y}) \sim p_{\text{data}}}[\ell(f_\theta(\mathbf{x}), \mathbf{y})] $.

### 6.1.2 The Train/Validation/Test Split

The empirical risk is a biased estimate of the true risk because it is computed on the same data used to train the model. To get an unbiased estimate, we split the data into three disjoint sets:

$$
\mathcal{D} = \mathcal{D}_{\text{train}} \cup \mathcal{D}_{\text{val}} \cup \mathcal{D}_{\text{test}}
$$

where:
- $ \mathcal{D}_{\text{train}} $ is used to fit the parameters $ \theta $.
- $ \mathcal{D}_{\text{val}} $ is used to tune hyperparameters and select the best model.
- $ \mathcal{D}_{\text{test}} $ is used to report final performance.

The typical split is 80/10/10 or 70/15/15. For small datasets, $ k $-fold cross-validation is preferred.

**Worked example 6.1:** Consider a dataset of $ N = 1000 $ samples. An 80/10/10 split gives:
- $ \mathcal{D}_{\text{train}} $: 800 samples
- $ \mathcal{D}_{\text{val}} $: 100 samples
- $ \mathcal{D}_{\text{test}} $: 100 samples

In PyTorch:

```python
import torch
from torch.utils.data import random_split, TensorDataset

# Assume x and y are tensors of shape (1000, ...)
dataset = TensorDataset(x, y)
train_size = int(0.8 * len(dataset))
val_size = int(0.1 * len(dataset))
test_size = len(dataset) - train_size - val_size

train_dataset, val_dataset, test_dataset = random_split(
    dataset, [train_size, val_size, test_size]
)
print(f"Train: {len(train_dataset)}, Val: {len(val_dataset)}, Test: {len(test_size)}")
```

### 6.1.3 The i.i.d. Assumption

Most learning theory assumes that the samples in $ \mathcal{D} $ are **independent and identically distributed** (i.i.d.):

$$
(\mathbf{x}_i, \mathbf{y}_i) \sim p_{\text{data}}(\mathbf{x}, \mathbf{y}), \quad \text{independent across } i
$$

This assumption is often violated in practice. Time series data is correlated across time. Image data from the same source is correlated. Medical data from the same patient is correlated. When the i.i.d. assumption is violated, the train/validation/test split must respect the correlation structure (e.g., split by patient, not by sample).

**Research relevance:** Violating the i.i.d. assumption is a common source of irreproducible results. Always check whether your data is i.i.d. and, if not, design your split accordingly.

### 6.1.4 Class Imbalance

For classification tasks, the class distribution $ p(y) $ may be imbalanced. For example, in medical diagnosis, 99% of samples may be negative and 1% positive. Training on imbalanced data leads to models that predict the majority class.

The **class weights** are:

$$
w_c = \frac{N}{C \cdot N_c}
$$

where $ N_c $ is the number of samples in class $ c $ and $ C $ is the number of classes. These weights are used in the loss function:

$$
\mathcal{L}(\theta) = \frac{1}{N} \sum_{i=1}^N w_{y_i} \ell(f_\theta(\mathbf{x}_i), y_i)
$$

**Worked example 6.2:** Consider a binary classification problem with $ N = 1000 $, $ N_0 = 990 $, $ N_1 = 10 $. The class weights are:

$$
w_0 = \frac{1000}{2 \cdot 990} \approx 0.505, \quad w_1 = \frac{1000}{2 \cdot 10} = 50
$$

The minority class is weighted 100× more than the majority class, compensating for the imbalance.

In PyTorch:

```python
class_weights = torch.tensor([0.505, 50.0])
loss_fn = nn.CrossEntropyLoss(weight=class_weights)
```

### 6.1.5 Summary: Data Mathematics

| Concept | Mathematical Form | PyTorch |
|---------|-------------------|---------|
| Data distribution | $ p_{\text{data}}(\mathbf{x}, \mathbf{y}) $ | — |
| Empirical risk | $ \frac{1}{N} \sum \ell(f_\theta(\mathbf{x}_i), \mathbf{y}_i) $ | `loss_fn` |
| Train/val/test split | $ \mathcal{D} = \mathcal{D}_{\text{train}} \cup \mathcal{D}_{\text{val}} \cup \mathcal{D}_{\text{test}} $ | `random_split` |
| i.i.d. assumption | $ (\mathbf{x}_i, \mathbf{y}_i) \sim p_{\text{data}} $ | — |
| Class weights | $ w_c = N / (C \cdot N_c) $ | `nn.CrossEntropyLoss(weight=...)` |

## 6.2 The `Dataset` Abstraction

### 6.2.1 What Is a Dataset?

A **Dataset** in PyTorch is an object that provides access to individual samples. It must implement two methods:

- `__len__`: returns the number of samples.
- `__getitem__(index)`: returns the sample at the given index.

Mathematically, a Dataset is a mapping:

$$
\text{Dataset}: \{0, 1, \ldots, N-1\} \to \mathcal{X} \times \mathcal{Y}
$$

where $ N $ is the number of samples.

### 6.2.2 The `TensorDataset`

The simplest Dataset is `TensorDataset`, which wraps tensors:

```python
from torch.utils.data import TensorDataset

x = torch.randn(100, 10)
y = torch.randn(100, 1)

dataset = TensorDataset(x, y)
print(f"Length: {len(dataset)}")
print(f"Sample 0: {dataset[0]}")
```

### 6.2.3 A Custom Dataset

For more complex data, define a custom Dataset:

```python
from torch.utils.data import Dataset

class CustomDataset(Dataset):
    def __init__(self, x_tensor, y_tensor):
        self.x = x_tensor
        self.y = y_tensor

    def __getitem__(self, index):
        return self.x[index], self.y[index]

    def __len__(self):
        return len(self.x)

dataset = CustomDataset(x, y)
print(f"Length: {len(dataset)}")
print(f"Sample 0: {dataset[0]}")
```

### 6.2.4 The Original Notebook's Example

The original notebook defines a `CustomDataset`:

```python

    def __getitem__(self, index):
        return (self.x[index], self.y[index])

    def __len__(self):
        return len(self.x)

# Wait, is this a CPU tensor now? Why? Where is .to(device)?
x_train_tensor = torch.from_numpy(x_train).float()
y_train_tensor = torch.from_numpy(y_train).float()

print(train_data[0])
```

The key observation: the dataset lives on the CPU, not the GPU. This is intentional. The `DataLoader` will move batches to the GPU during training.

### 6.2.5 Dataset Design Principles

When designing a Dataset for research:

1. **Keep data on CPU.** The GPU is for computation, not storage. Moving the entire dataset to GPU wastes memory and prevents parallel loading.
2. **Return tensors, not NumPy arrays.** PyTorch expects tensors.
3. **Apply transforms lazily.** Data augmentation should happen in `__getitem__`, not in `__init__`, so that each epoch sees different augmentations.
4. **Handle edge cases.** What if the file is missing? What if the tensor has the wrong shape?
5. **Make it reproducible.** If your Dataset uses randomness, seed it.

### 6.2.6 Summary: Dataset

| Method | Description | Example |
|--------|-------------|---------|
| `__init__` | Initialize dataset | `self.x = x_tensor` |
| `__len__` | Return number of samples | `return len(self.x)` |
| `__getitem__` | Return sample at index | `return self.x[index], self.y[index]` |
| `TensorDataset` | Wrap tensors | `TensorDataset(x, y)` |
| `random_split` | Split dataset | `random_split(dataset, [80, 20])` |

## 6.3 The `DataLoader` Abstraction

### 6.3.1 What Is a DataLoader?

A **DataLoader** wraps a Dataset and provides:
- **Batching:** Groups samples into mini-batches.
- **Shuffling:** Randomizes the order of samples each epoch.
- **Parallel loading:** Uses multiple workers to load data.
- **Collation:** Combines samples into batches.

Mathematically, a DataLoader produces a sequence of mini-batches:

$$
\mathcal{B}_1, \mathcal{B}_2, \ldots, \mathcal{B}_{N/B}
$$

where each $ \mathcal{B}_k \subset \mathcal{D} $ has size $ B $.

### 6.3.2 Creating a DataLoader

```python
from torch.utils.data import DataLoader

train_loader = DataLoader(
    dataset=train_data,
    batch_size=16,
    shuffle=True,
    num_workers=4,
    pin_memory=True
)
```

| Parameter | Description | Default |
|-----------|-------------|---------|
| `batch_size` | Number of samples per batch | 1 |
| `shuffle` | Shuffle data each epoch | False |
| `num_workers` | Number of parallel workers | 0 |
| `pin_memory` | Pin memory for faster GPU transfer | False |
| `drop_last` | Drop incomplete last batch | False |
| `collate_fn` | Custom collation function | `default_collate` |

### 6.3.3 Iterating Over a DataLoader

```python
for x_batch, y_batch in train_loader:
    print(f"Batch shape: {x_batch.shape}, {y_batch.shape}")
    break
```

The original notebook shows:

```python
next(iter(train_loader))
```

which returns the first batch.

### 6.3.4 The `num_workers` Parameter

`num_workers` controls how many subprocesses are used to load data. With `num_workers=0`, data is loaded in the main process. With `num_workers>0`, data is loaded in parallel, which can significantly speed up training when data loading is the bottleneck.

**Research relevance:** For large datasets (e.g., ImageNet), `num_workers=4` or `num_workers=8` is standard. For small datasets, `num_workers=0` is fine. Setting `num_workers` too high can cause memory issues.

### 6.3.5 The `pin_memory` Parameter

`pin_memory=True` pins the loaded data in CPU memory, which allows faster transfer to GPU. This is recommended when training on GPU.

### 6.3.6 Custom Collation

For variable-length sequences (e.g., text), the default collation fails because samples have different shapes. You must provide a `collate_fn`:

```python
def collate_fn(batch):
    # batch is a list of (x, y) tuples
    x_list, y_list = zip(*batch)
    # Pad sequences to the same length
    x_padded = torch.nn.utils.rnn.pad_sequence(x_list, batch_first=True)
    y = torch.stack(y_list)
    return x_padded, y

loader = DataLoader(dataset, batch_size=32, collate_fn=collate_fn)
```

### 6.3.7 Summary: DataLoader

| Parameter | Description | Recommendation |
|-----------|-------------|----------------|
| `batch_size` | Samples per batch | 32–256 for most tasks |
| `shuffle` | Shuffle each epoch | True for training, False for val/test |
| `num_workers` | Parallel workers | 4–8 for large datasets |
| `pin_memory` | Pin memory for GPU | True when training on GPU |
| `drop_last` | Drop incomplete last batch | True for batch norm |
| `collate_fn` | Custom collation | For variable-length data |

## 6.4 Tabular Data: Excel and CSV

### 6.4.1 The Tabular Data Problem

Tabular data is the most common data format in industry and research. It consists of a table with rows (samples) and columns (features). The features can be numerical (continuous or discrete) or categorical (strings).

Mathematically, a tabular dataset is a matrix $ X \in \mathbb{R}^{N \times d} $ and a target vector $ \mathbf{y} \in \mathbb{R}^N $ (regression) or $ \mathbf{y} \in \{1, \ldots, C\}^N $ (classification).

### 6.4.2 Loading Excel Data

Excel files are loaded with `pandas`:

```python
import pandas as pd
import numpy as np
import torch
from torch.utils.data import Dataset, DataLoader

# Load Excel file
df = pd.read_excel('data.xlsx')
print(df.head())
print(df.shape)
print(df.dtypes)
```

**Worked example 6.3:** Consider a welding process dataset with columns `Current`, `Angle`, `Speed`, `Time`, and `Height` (target). The goal is to predict `Height` from the other features.

```python
# Load data
df = pd.read_excel('welding_data.xlsx')

# Separate features and target
X = df[['Current', 'Angle', 'Speed', 'Time']].values
y = df['Height'].values

# Convert to tensors
X = torch.tensor(X, dtype=torch.float32)
y = torch.tensor(y, dtype=torch.float32).unsqueeze(1)

print(f"X shape: {X.shape}")
print(f"y shape: {y.shape}")
```

### 6.4.3 Preprocessing Tabular Data

Tabular data often requires preprocessing:

**Normalization:** Scale features to have mean 0 and std 1:

$$
x_{\text{norm}} = \frac{x - \mu}{\sigma}
$$

**Standardization:** Scale features to a fixed range:

$$
x_{\text{std}} = \frac{x - x_{\min}}{x_{\max} - x_{\min}}
$$

**One-hot encoding:** Convert categorical features to binary vectors.

**Handling missing values:** Impute with mean, median, or model-based imputation.

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)
X_scaled = torch.tensor(X_scaled, dtype=torch.float32)

print(f"Mean: {X_scaled.mean(dim=0)}")
print(f"Std: {X_scaled.std(dim=0)}")
```

**Research relevance:** Preprocessing must be fit on the training set only, then applied to the validation and test sets. Fitting on the full dataset leaks information and inflates performance.

### 6.4.4 A Custom Dataset for Tabular Data

```python
class TabularDataset(Dataset):
    def __init__(self, X, y):
        self.X = X
        self.y = y

    def __getitem__(self, index):
        return self.X[index], self.y[index]

    def __len__(self):
        return len(self.X)

# Split
from torch.utils.data import random_split
dataset = TabularDataset(X_scaled, y)
train_size = int(0.8 * len(dataset))
val_size = len(dataset) - train_size
train_dataset, val_dataset = random_split(dataset, [train_size, val_size])

# DataLoaders
train_loader = DataLoader(train_dataset, batch_size=32, shuffle=True)
val_loader = DataLoader(val_dataset, batch_size=32, shuffle=False)
```

### 6.4.5 Research Relevance

Tabular data is often used as a baseline in research. Neural networks do not always outperform gradient boosting on tabular data. When designing a study, always include a strong baseline (e.g., XGBoost) alongside your neural network.

| Preprocess | Normalize, encode, impute | `sklearn.preprocessing` |

## 6.5 Image Data

### 6.5.1 The Image Data Problem

Images are 3-dimensional tensors $ \mathbf{X} \in \mathbb{R}^{C \times H \times W} $, where $ C $ is the number of channels (1 for grayscale, 3 for RGB), $ H $ is the height, and $ W $ is the width. A batch of images is a 4-tensor $ \mathcal{X} \in \mathbb{R}^{N \times C \times H \times W} $.

### 6.5.2 Loading Image Data

Images are typically stored in a folder structure:

```
data/
  train/
    class_1/
      img1.jpg
      img2.jpg
    class_2/
      img1.jpg
      img2.jpg
  val/
    class_1/
      img1.jpg
    class_2/
      img1.jpg
```

PyTorch provides `ImageFolder` for this structure:

```python
from torchvision import datasets, transforms

transform = transforms.Compose([
    transforms.Resize((224, 224)),
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])
])

train_dataset = datasets.ImageFolder('data/train', transform=transform)
val_dataset = datasets.ImageFolder('data/val', transform=transform)

train_loader = DataLoader(train_dataset, batch_size=32, shuffle=True)
val_loader = DataLoader(val_dataset, batch_size=32, shuffle=False)

print(f"Classes: {train_dataset.classes}")
print(f"Number of training samples: {len(train_dataset)}")
```

### 6.5.3 Data Augmentation

Data augmentation applies random transformations to increase the diversity of the training set:

```python
train_transform = transforms.Compose([
    transforms.RandomResizedCrop(224),
    transforms.RandomHorizontalFlip(),
    transforms.ColorJitter(brightness=0.2, contrast=0.2, saturation=0.2),
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])
])

val_transform = transforms.Compose([
    transforms.Resize(256),
    transforms.CenterCrop(224),
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])
])
```

**Research relevance:** Data augmentation is a form of regularization. It encodes prior knowledge about the task (e.g., images are invariant to horizontal flips). The choice of augmentation is a hyperparameter that should be tuned.

### 6.5.4 A Custom Dataset for Images

For more complex scenarios (e.g., multi-label classification, segmentation), define a custom Dataset:

```python
from PIL import Image
import os

class CustomImageDataset(Dataset):
    def __init__(self, img_dir, labels_df, transform=None):
        self.img_dir = img_dir
        self.labels_df = labels_df
        self.transform = transform

    def __getitem__(self, index):
        img_name = self.labels_df.iloc[index, 0]
        img_path = os.path.join(self.img_dir, img_name)
        image = Image.open(img_path).convert('RGB')
        label = self.labels_df.iloc[index, 1]

        if self.transform:
            image = self.transform(image)

        return image, label

    def __len__(self):
        return len(self.labels_df)
```

### 6.5.5 Normalization Statistics

The mean and std used for normalization are typically the ImageNet statistics:

$$
\mu = [0.485, 0.456, 0.406], \quad \sigma = [0.229, 0.224, 0.225]
$$

For your own dataset, you can compute the statistics:

```python
def compute_mean_std(loader):
    mean = 0.0
    std = 0.0
    total_images = 0
    for images, _ in loader:
        batch_samples = images.size(0)
        images = images.view(batch_samples, images.size(1), -1)
        mean += images.mean(2).sum(0)
        std += images.std(2).sum(0)
        total_images += batch_samples
    mean /= total_images
    std /= total_images
    return mean, std
```

### 6.5.6 Research Relevance

Image data is the most common modality in deep learning research. The choice of preprocessing, augmentation, and normalization significantly affects results. When reproducing a paper, always check whether the authors specify their preprocessing pipeline.

## 6.6 Text Data

### 6.6.1 The Text Data Problem

Text is a sequence of tokens $ \mathbf{x} = (x_1, x_2, \ldots, x_L) $, where each token $ x_i $ is an integer index into a vocabulary $ \mathcal{V} $. A batch of text sequences is a tensor $ \mathcal{X} \in \mathbb{Z}^{N \times L} $.

### 6.6.2 Tokenization

Tokenization converts text to sequences of integers:

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained('bert-base-uncased')
text = "PyTorch is a deep learning framework."
tokens = tokenizer(text, return_tensors='pt', padding=True, truncation=True)
print(tokens)
```

### 6.6.3 A Custom Dataset for Text

```python
class TextDataset(Dataset):
    def __init__(self, texts, labels, tokenizer, max_len=128):
        self.texts = texts
        self.labels = labels
        self.tokenizer = tokenizer
        self.max_len = max_len

    def __getitem__(self, index):
        text = self.texts[index]
        label = self.labels[index]
        encoding = self.tokenizer(
            text,
            max_length=self.max_len,
            padding='max_length',
            truncation=True,
            return_tensors='pt'
        )
        return {
            'input_ids': encoding['input_ids'].squeeze(0),
            'attention_mask': encoding['attention_mask'].squeeze(0),
            'label': torch.tensor(label, dtype=torch.long)
        }

    def __len__(self):
        return len(self.texts)
```

### 6.6.4 Variable-Length Sequences

Text sequences have variable lengths. The `DataLoader` requires all samples in a batch to have the same shape. Two strategies:

**Padding:** Pad all sequences to the maximum length in the batch (or a fixed maximum).

**Bucketing:** Group sequences of similar lengths into the same batch.

```python
from torch.nn.utils.rnn import pad_sequence

def collate_fn(batch):
    input_ids = [item['input_ids'] for item in batch]
    attention_mask = [item['attention_mask'] for item in batch]
    labels = torch.stack([item['label'] for item in batch])

    input_ids = pad_sequence(input_ids, batch_first=True, padding_value=0)
    attention_mask = pad_sequence(attention_mask, batch_first=True, padding_value=0)

    return {
        'input_ids': input_ids,
        'attention_mask': attention_mask,
        'labels': labels
    }
```

### 6.6.5 Research Relevance

Text data is the dominant modality in NLP research. The choice of tokenizer, maximum length, and padding strategy affects both performance and efficiency. When reproducing a paper, always check whether the authors specify their tokenization pipeline.

### 6.6.6 Summary: Text Data

| Step | Description | Tool |
|------|-------------|------|
| Tokenize | Convert text to integers | `transformers.AutoTokenizer` |
| Pad | Pad to fixed length | `pad_sequence` |
| Truncate | Truncate long sequences | `truncation=True` |
| Wrap | Custom Dataset | `Dataset` |

## 6.7 Handling Imbalanced Datasets

### 6.7.1 The Imbalance Problem

In many real-world datasets, classes are imbalanced. For example, in fraud detection, 0.1% of transactions are fraudulent. Training on imbalanced data leads to models that predict the majority class.

### 6.7.2 Strategies for Imbalance

**Class weighting:** Weight the loss by inverse class frequency:

$$
w_c = \frac{N}{C \cdot N_c}
$$

```python
class_weights = torch.tensor([1.0 / N_c for N_c in class_counts])
class_weights = class_weights / class_weights.sum() * len(class_counts)
loss_fn = nn.CrossEntropyLoss(weight=class_weights)
```

**Oversampling:** Duplicate samples from the minority class.

**Undersampling:** Remove samples from the majority class.

**SMOTE:** Synthesize new samples from the minority class.

**Focal loss:** Down-weight easy examples:

$$
\ell_{\text{focal}}(y, \hat{y}) = -(1 - \hat{y})^\gamma y \log \hat{y}
$$

where $ \gamma $ is a focusing parameter.

### 6.7.3 Weighted Random Sampler

PyTorch provides `WeightedRandomSampler` to oversample the minority class:

```python
from torch.utils.data import WeightedRandomSampler

class_counts = np.bincount(labels)
class_weights = 1.0 / class_counts
sample_weights = class_weights[labels]

sampler = WeightedRandomSampler(
    weights=sample_weights,
    num_samples=len(sample_weights),
    replacement=True
)

train_loader = DataLoader(dataset, batch_size=32, sampler=sampler)
```

### 6.7.4 Research Relevance

Class imbalance is common in real-world datasets. When reporting results, always report per-class metrics (precision, recall, F1) in addition to overall accuracy. A model with 99% accuracy on a 99/1 dataset may be useless.

### 6.7.5 Summary: Imbalance

| Strategy | Description | PyTorch |
|----------|-------------|---------|
| Class weighting | Weight loss by inverse frequency | `nn.CrossEntropyLoss(weight=...)` |
| Oversampling | Duplicate minority samples | `WeightedRandomSampler` |
| Undersampling | Remove majority samples | Custom sampler |
| SMOTE | Synthesize minority samples | `imblearn` |
| Focal loss | Down-weight easy examples | Custom loss |

## 6.8 Worked Example: Full Data Pipeline

Let us combine everything we have learned into a complete data pipeline for a tabular regression task.

### 6.8.1 Load Data

```python
import pandas as pd
import numpy as np
import torch
from torch.utils.data import Dataset, DataLoader, random_split
from sklearn.preprocessing import StandardScaler

# Load Excel file
df = pd.read_excel('data.xlsx')
X = df[['feature1', 'feature2', 'feature3']].values
y = df['target'].values

print(f"X shape: {X.shape}, y shape: {y.shape}")
```

### 6.8.2 Preprocess

```python
# Split first, then scale
N = len(X)
idx = np.random.permutation(N)
train_idx = idx[:int(0.7 * N)]
val_idx = idx[int(0.7 * N):int(0.85 * N)]
test_idx = idx[int(0.85 * N):]

scaler = StandardScaler()
X_train = scaler.fit_transform(X[train_idx])
X_val = scaler.transform(X[val_idx])
X_test = scaler.transform(X[test_idx])

y_train = y[train_idx]
y_val = y[val_idx]
y_test = y[test_idx]
```

### 6.8.3 Create Datasets and DataLoaders

```python
class TabularDataset(Dataset):
    def __init__(self, X, y):
        self.X = torch.tensor(X, dtype=torch.float32)
        self.y = torch.tensor(y, dtype=torch.float32).unsqueeze(1)

    def __getitem__(self, index):
        return self.X[index], self.y[index]

    def __len__(self):
        return len(self.X)

train_dataset = TabularDataset(X_train, y_train)
val_dataset = TabularDataset(X_val, y_val)
test_dataset = TabularDataset(X_test, y_test)

train_loader = DataLoader(train_dataset, batch_size=32, shuffle=True)
val_loader = DataLoader(val_dataset, batch_size=32, shuffle=False)
test_loader = DataLoader(test_dataset, batch_size=32, shuffle=False)
```

### 6.8.4 Train a Model

```python
import torch.nn as nn
import torch.optim as optim

class MLP(nn.Module):
    def __init__(self, input_dim, hidden_dim=64):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, 1)
        )

    def forward(self, x):
        return self.net(x)

device = "cuda" if torch.cuda.is_available() else "cpu"
model = MLP(input_dim=X_train.shape[1]).to(device)
loss_fn = nn.MSELoss()
optimizer = optim.Adam(model.parameters(), lr=1e-3)

for epoch in range(100):
    model.train()
    for x_batch, y_batch in train_loader:
        x_batch, y_batch = x_batch.to(device), y_batch.to(device)
        yhat = model(x_batch)
        loss = loss_fn(y_batch, yhat)
        loss.backward()
        optimizer.step()
        optimizer.zero_grad()

    # Validation
    model.eval()
    val_losses = []
    with torch.no_grad():
        for x_batch, y_batch in val_loader:
            x_batch, y_batch = x_batch.to(device), y_batch.to(device)
            yhat = model(x_batch)
            val_losses.append(loss_fn(y_batch, yhat).item())

    if epoch % 10 == 0:
        print(f"Epoch {epoch}: val_loss={np.mean(val_losses):.4f}")
```

### 6.8.5 Evaluate on Test Set

```python
model.eval()
test_losses = []
with torch.no_grad():
    for x_batch, y_batch in test_loader:
        x_batch, y_batch = x_batch.to(device), y_batch.to(device)
        yhat = model(x_batch)
        test_losses.append(loss_fn(y_batch, yhat).item())

print(f"Test loss: {np.mean(test_losses):.4f}")
```

### 6.8.6 Reflection

This pipeline illustrates the full data workflow. The data is loaded from Excel, split into train/val/test, scaled (with the scaler fit on the training set only), wrapped in a custom Dataset, batched with DataLoader, and fed to a model. The model is trained, validated, and tested. The pipeline respects the i.i.d. assumption, avoids data leakage, and is reproducible.

**Research relevance:** This is the canonical data pipeline in PyTorch. Every research project you run will follow this structure, with modifications for the specific data modality and task.

## 6.9 Common Errors and Debugging

### 6.9.1 Error: `RuntimeError: DataLoader worker (pid(s) ...) exited unexpectedly`

**Cause:** A worker crashed, often due to a bug in the Dataset or a memory issue.

**Fix:** Set `num_workers=0` to debug in the main process.

### 6.9.2 Error: `TypeError: default_collate: batch must contain tensors, numpy arrays, numbers, dicts or lists`

**Cause:** The Dataset returns an unsupported type (e.g., a PIL Image).

**Fix:** Convert to tensors in `__getitem__` or provide a custom `collate_fn`.

### 6.9.3 Error: `RuntimeError: CUDA out of memory`

**Cause:** The batch is too large for the GPU.

**Fix:** Reduce `batch_size`, use gradient accumulation, or use mixed precision.

### 6.9.4 Error: Data leakage

**Symptom:** Validation performance is suspiciously high.

**Cause:** Preprocessing was fit on the full dataset, or the split was not random.

**Fix:** Split first, then fit preprocessing on the training set only.

### 6.9.5 Summary: Common Data Errors

| Error | Cause | Fix |
|-------|-------|-----|
| Worker crashed | Bug in Dataset | `num_workers=0` |
| `default_collate` | Unsupported type | Custom `collate_fn` |
| CUDA OOM | Batch too large | Reduce batch size |
| Data leakage | Wrong split | Split first, then preprocess |

## 6.10 Research Application: Data Versioning and Reproducibility

### 6.10.1 Why Data Versioning Matters

In research, the data is as important as the code. If the data changes between runs, the results are not reproducible. Data versioning tools like DVC (Data Version Control) and Git LFS allow you to version data alongside code.

### 6.10.2 Data Cards

A **data card** is a document that describes a dataset:
- Motivation: why was the dataset created?
- Composition: what are the samples?
- Collection process: how was the data collected?
- Preprocessing: what transformations were applied?
- Uses: what tasks is the dataset suitable for?
- Limitations: what are the known biases?

**Research relevance:** Data cards are increasingly required by conferences and journals. They improve reproducibility and transparency.

### 6.10.3 Summary: Data Reproducibility

| Aspect | Tool | Description |
|--------|------|-------------|
| Versioning | DVC, Git LFS | Track data changes |
| Documentation | Data cards | Describe the dataset |
| Splits | Fixed seeds | Reproducible splits |
| Preprocessing | Scripts | Versioned preprocessing |
| Augmentation | Seeds | Reproducible augmentation |
